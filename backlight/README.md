# ddcci

Управление яркостью мониторов через DDC/CI. Быстрый путь — ядро (`/sys/class/backlight/ddcci*`),
запасной — `ddcutil` по i2c-шине для мониторов, к которым ddcci не смог прицепиться.

## Файлы

- `ddcci@.service` — подключает `ddcci` к i2c-адаптеру GPU (`%i` = `i2c-N`).
  Запускается udev-правилом, сам грузит `ddcci_backlight`. Если монитор ещё
  спит (DDC/CI отвечает `-ENODEV`), повторяет попытку ~30 секунд. Если
  `ddcutil` стабильно видит DDC/CI (5 попыток подряд), а ddcci так и не
  прицепился, юнит завершается и оставляет шину `ddcutil` (монитор с битым
  identification/capabilities). Порог нужен, потому что некоторым мониторам
  после холодной загрузки требуется 2–3 попытки. Если модуль недоступен —
  сразу выходит.
- `99-ddcci.rules` — `SYSTEMD_WANTS=ddcci@$kernel.service` для i2c-адаптеров
  видеокарты (`ATTRS{class}=="0x03*"`: NVIDIA/AMD/Intel). SMBus и клиентские
  устройства не затрагиваются, `i2c-dev` не требуется.
- `blacklist.conf` — запрещает автозагрузку ddcci; модуль грузится явно сервисом.
- `fix-dkms.sh` — патч `strncpy` → `strscpy` и пересборка DKMS-модуля.
- `dkms-strscpy.patch` — сам патч для исходников ddcci.

## Как бар находит подсветку

`scripts/backlight-map.sh` печатает JSON-карту `{ "DP-1": "ddcci4", ... }`:

1. по `idModel`/`idSerial` подсветки (быстро, без DDC-запросов);
2. если модели неоднозначны — через DRM-коннектор → i2c-шину (`ddcutil detect`);
3. для ноутбука — единственный монитор и единственная подсветка.

Если ddcci не прицепился, но `ddcutil getvcp 10 --bus N` работает, в карте
будет `"ddcutil:N"`. Если DDC/CI не отвечает вообще, записи нет и виджет
яркости на этом мониторе скрыт. Карта кешируется в
`/run/user/<uid>/eww-backlight-map.cache` и пересчитывается при изменении
набора мониторов или подсветок. Если внешний монитор остался без backend'а
(спал при загрузке, ещё не ответил на DDC/CI), неполная карта кешируется
только на 15 секунд — потом пересчитывается, чтобы монитор появился сам.
eww опрашивает её раз в 5 секунд.

При старте бара и при hotplug (`monitor.sh` → `launch_bar`) повторяется
udev-add для i2c-адаптеров, чтобы подхватить монитор, проснувшийся позже
загрузки, или подключённый после неё.

## Как управляется яркость

`scripts/brightness.sh` умеет оба backend'а: `ddcciN` пишет напрямую в sysfs,
`ddcutil:<bus>` — через `ddcutil`. DDC-запись занимает десятки-сотни мс,
поэтому виджет не ждёт её: значение сразу обновляется в eww, а в монитор его
пишет фоновый worker. Серия событий быстрого скролла склеивается в одну
запись последнего значения; уведомление dunst с моделью и коннектором монитора
(например, `DELL P2214H (DP-1)`) показывается
один раз на итоговое значение. Опрос `brightness` — раз в 5 секунд, после
прокрутки/клика значение обновляется сразу через `eww update`.

## Сборка модуля на новых ядрах

В ядре убрали `strncpy`, поэтому ddcci 0.4.5 из AUR не собирается: DKMS
остаётся в состоянии `added`, `ddcci_backlight` не загружается, подсветка
`ddcci*` не появляется.

После обновления ядра/пакета ddcci:

```sh
~/dotfiles/backlight/fix-dkms.sh
```

Скрипт находит исходник в `/usr/src/ddcci-*`, берёт имя пакета и версию из
`dkms.conf`, применяет патч и пересобирает модуль. Повторный запуск безопасен.
